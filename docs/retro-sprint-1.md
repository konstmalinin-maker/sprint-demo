# Ретроспектива Sprint 1

Дата: 29.09.2026.
Участник: Малинин Константин Николаевич.
Формат: индивидуальная ретроспектива Start / Stop / Continue.

## Continue — продолжить
- Разрабатывать каждую функцию в отдельной feature-ветке.
- Делать отдельные коммиты для реализации и тестов.
- Проверять изменения перед объединением PR.
- Фиксировать замечания и ответы в обсуждениях PR.
- Запускать все тесты после интеграции функций.

## Stop — прекратить
- Создавать коммиты без проверки текущей ветки:
  коммиты авторизации первоначально попали в sprint-1.
- Считать отдельные успешные проверки функций достаточными
  без общего запуска тестов после слияния.

## Start — начать
- Проверять текущую ветку перед изменением файлов и коммитом.
- Заранее согласовывать изменения общего файла:
  просмотр и создание задач затронули src/tasks.py.
- Добавлять проверки граничных случаев при разработке,
  а не только после замечаний самопроверки.

## Action Items
- [ ] Перед каждым коммитом выполнять git branch --show-current.
- [ ] Перед следующим спринтом определить, какие функции
      будут изменять общие файлы.
- [ ] В следующем спринте включать граничные случаи
      в первоначальный набор тестов.
